# 부기2 개선 설계

## 문제와 선택

기존 앱은 독서 자료와 수업 도구가 갖춰져 있지만 진단 결과가 다음 본문과 연결되지 않는다. 연결이 먼저다. 부기2는 새 메뉴를 늘리기보다 ‘낱말 응답 → 교사 확인 → 본문 배정 → 학생 설명 → 교사 피드백’을 한 흐름으로 만든다.

가장 무거운 조건은 진단 비공개다. 화면을 숨기는 수준으로 처리하지 않는다. 학생 계정으로 조회하는 API는 점수·영역·추천 수준을 반환하지 않고, 담당 교사인지 서버에서 확인한 요청만 진단을 받는다. 학생에게 반환하는 본문에도 수준 키를 넣지 않는다.

## 기존 자료와 차이

| 자료의 요구 | 부기2 처리 | 남은 작업 |
|---|---|---|
| 어휘·사실·추론·비판·창의·유창성 진단 | 어휘 시범 문항과 교사 응답 확인을 먼저 구현 | 나머지 영역을 관찰 가능한 과제로 정의하고 문항 검토 |
| BGI 통합 지수·학생 레벨 | 진단 결과는 학생에게 보내지 않음. 기록 수와 학생 문장만 표시 | 학생의 능력을 자동 추정하는 지수는 검증 자료를 확보한 뒤 교사용으로 검토 |
| 수준별 읽기 | 세 수준 원고 중 교사가 확인한 글을 전달 | 학년별 진단과 본문 난도 사이 연결 기준 검증 |
| 성장 그래프 | 동일 검사 이력은 교사에게, 처음·나중 문장 비교는 학생과 교사에게 제공 | 동등 문항·독립 수행 과제로 비교 근거 확보 |
| 나의 한 페이지·문집 | 개인 기록·교사 한마디·인쇄 구현 | 학생 선택 작품 모으기·학급 문집 편집·내보내기 |
| 작가·인물 AI | 아직 연결하지 않음 | 본문 근거, 상상 표시, 대화 보존, 실패 시 대체 질문 |
| 기존 수업 설계·미션·그림 | 원래 앱에서 유지 | 책·활동 식별자를 맞춘 뒤 기능별 통합 |

## 데이터 경계

teacher는 자신이 만든 classes에 속한 학생만 조회한다. student는 자기의 열린 진단, 배정된 본문, 자기 기록과 공개 피드백만 읽는다. 익명 사용자에게 진단·학생 기록은 반환하지 않는다. 학생이 교사 결과 주소를 직접 요청하면 차단한다.

진단은 attempts에, 본문 배정은 plans에 저장한다. 분리한다. 학생이 보는 계획은 bookId·title·goal만 포함한다. 채점 결과와 본문 구성 키는 학생 응답에 포함하지 않는다. 교사가 학생에게 쓰는 활동 문장과 한마디에는 진단 수치를 적지 않는다.

한 번 제출한 진단을 같은 요청으로 다시 보내도 처음 결과를 유지한다. 새 진단은 교사가 연다. 생각 기록은 고유 ID로 저장해 재시도 중복을 막는다. 학생 삭제는 진단·계획·작품·교사 한마디·세션을 함께 삭제한다.

## 콘텐츠 처리

본문 120권·360편은 기존 집필 초안을 사용한다. 그대로다. 페이지 넘김을 장면 단위로 바꾸고 낱말 뜻과 질문을 같은 책에서 가져왔다. ‘교사 검토 전’ 상태를 화면에 표시하고 실제 계정 배포 때 확인 표시를 받는다.

현재 진단 12문항은 초급 이야기 어휘를 확인하는 검토용이다. 범위가 좁다. 이를 1~6학년 학생의 일반 어휘력으로 표시하지 않는다. 성적 검사로 사용할 문항은 문항별 검토·동등 검사·비공개 배포 절차를 갖춘 뒤 교체한다.

## 다음 구현 순서

먼저 진단 문항과 본문 난도 기준을 교육 검토자가 확인한다. 근거가 우선이다. 문항 버전·독해 지원 조건·읽기 활동 근거를 확정한 뒤, 책별 수업 결과가 부기2 기록으로 이어지도록 연결한다.

다음에는 학생이 남긴 대화·그림·글에서 공유할 작품을 고르게 한다. 선택을 남긴다. 학급 문집과 가정용 인쇄에는 진단·교사 내부 관찰이 섞이지 않는지 별도로 검사한다.

실시간 인물 대화는 근거 문장을 전달하고 답을 검증할 서버 기능을 만든 뒤 연결한다. 표시도 필요하다. 책에 없는 상상은 ‘이야기를 바탕으로 상상한 말’이라고 적고 원문 장면으로 돌아가는 버튼을 둔다.
