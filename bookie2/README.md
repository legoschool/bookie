# 부기2

부기2는 낱말 진단, 교사의 본문 배정, 학생의 생각 기록을 연결한 별도 앱이다. 기존 운영 부기의 계정·데이터베이스와 분리한다.

공개 체험: https://legoschool.github.io/bookie/

## 실행한 기능

| 사용 장면 | 구현 내용 |
|---|---|
| 교사가 낱말 활동을 연다 | 담당 학생에게만 활동을 배정한다. 열린 활동은 중복 생성하지 않는다. |
| 학생이 응답한다 | 12문항을 한 문항씩 읽고 답하거나 ‘아직 모르겠어요’를 고른다. 서버에는 응답을 보내고 접수 여부만 받는다. |
| 교사가 진단 근거를 읽는다 | 낱말 뜻·문맥 속 뜻·낱말 관계, 문항별 학생 응답, 동일 검사 이력을 확인한다. 다른 교사의 학생은 조회하지 못한다. |
| 다음 본문을 준비한다 | 120권의 세 수준 원고를 미리 읽고 검토 표시 후 배정한다. 학생 응답만으로 자동 배포하지 않는다. |
| 학생이 책을 읽는다 | 배정된 본문과 활동만 전달한다. 본문 수준 이름, 진단 점수, 정답 여부는 보내지 않는다. 글씨 크기·장면 듣기·낱말 뜻·읽던 위치 복귀를 제공한다. |
| 생각을 남긴다 | 처음 생각, 근거 장면, 다시 쓴 생각, 남은 질문을 저장한다. 교사가 한마디를 전달한다. |
| 성장을 살핀다 | 실제 학생 문장을 나란히 놓는다. 기록 수를 능력 점수로 해석하지 않는다. 학생 기록장은 인쇄할 수 있다. |
| 학급을 운영한다 | 교사별 학급, 학생 계정, 로그인 만료·로그아웃, 학생 계정과 관련 기록 삭제를 구현했다. |

## 진단의 범위

현재 문항은 「토끼와 거북이」 어휘로 만든 시범 문항이다. 표준화 검사도, 학년별 어휘력 규준도 아니다. 정답표는 공개 저장소에 포함하지 않고 서버 데이터베이스에만 등록한다. 검토용 문항으로만 사용한다. 실제 진단 도구를 확정할 때 검토한 문항을 비공개 문항 저장소에 넣고 별도 문항 버전을 발급해야 한다.

정답 수에 따른 쉬움·중간·어려움 제안은 임시 운영 기준이다. 교사가 수업 관찰과 응답을 보고 바꾼다. 재검사는 같은 문항에 익숙해진 영향을 포함하므로 점수 차이를 성장률로 표시하지 않는다.

## 자료 출처와 적용 판단

로컬 ‘부기 개발 방향 협의_2026-09-12/본문과 독후활동/수준별 집필 데이터.json’의 120권·360편을 연결했다. ‘집필 초안, 교사 검토 전’ 상태를 유지했다. 중복된 문맥 문자열을 줄였고, 본문 장면·낱말 뜻·활동 질문은 원고에서 가져왔다.

‘독후대화 중심 구조 개선안.md’의 처음 생각·본문 근거·나중 생각 비교를 기록장에 반영했다. ‘Bookie 안내서_성장지표.pdf’의 학생 점수·레벨 공개안은 사용자의 비공개 요청에 따라 적용하지 않았다. ‘Bookie 안내서_나도 창작자.pdf’의 한 페이지를 생각 기록과 인쇄로 연결했다. 자동 출판·인물 AI 대화·기존 수업 도구 전체 이식은 아직 구현하지 않았다.

기존 코드 검토 기준은 HRYoon0/bookie의 3607b03 로컬 검토본이다. 기존 부기 운영 앱은 Cloudflare Pages Functions와 KV를 사용한다. 부기2는 별도 D1 저장소를 사용하도록 구성해 기존 컬렉션을 읽거나 덮어쓰지 않는다.

## 폴더

| 경로 | 역할 |
|---|---|
| public/ | GitHub Pages 체험 및 서버 연결 화면 |
| server/api.mjs | 역할·학급 권한, 진단 제출, 교사 조회, 본문 배정, 생각 기록 |
| server/assessment.mjs | 정답표 없는 공통 채점 코드 |

| server/local.mjs | 로컬 검증 서버 |
| functions/api/[[path]].js | Cloudflare Pages 서버 진입점 |
| tests/ | 권한 검사와 브라우저 흐름 검사 |
| docs/ | 개선 설계와 배포 기록 |

## 로컬 실행

Node.js 24 이상을 설치하고 이 폴더에서 `npm start`를 실행하면 http://127.0.0.1:4173 에서 열린다. 별도 패키지는 필요 없다. 실제 계정 테스트에는 `BOOKIE_TEACHER_PASSWORD` 환경변수에 12자 이상 비밀번호를 넣고 시작한다. 교사 아이디 기본값은 `teacher`다. 운영 비밀번호를 코드나 커밋에 넣지 않는다.

기본 로컬 데이터베이스는 운영체제 임시 폴더의 bookie2-local/bookie.sqlite다. 보존할 개발 기록이 있으면 `BOOKIE_DATA_DIR`에 동기화 드라이브가 아닌 로컬 폴더를 지정한다. Google Drive 가상 드라이브는 SQLite 잠금을 지원하지 않을 수 있다. 로컬 실행에는 실제 학생 정보를 넣지 않는다.

검사: `npm test`와 `npm run check`. 브라우저 검사는 `tests/browser.cjs`, `tests/live-browser.cjs`이며 현재 작업 컴퓨터의 Playwright·Chrome 경로를 사용한다.

## 별도 서버 배포

GitHub Pages는 서버 함수를 실행하지 않는다. 공개 체험의 응답은 채점·저장하지 않으며 교사 결과는 고정된 가상 예시다. 실제 로그인은 별도 서버 배포 후 사용한다.

비공개 `.local/assessment-bank.json` 문항 파일을 준비하고 Cloudflare 인증 후 `node tools/deploy.mjs`를 실행한다. 이 파일은 공개 저장소에 올리지 않는다. 새 Pages 프로젝트 `bookie2-legoschool`과 새 D1 데이터베이스 `bookie2-legoschool-db`만 대상으로 한다. 실행 도중 기존 운영 부기 프로젝트를 지정하지 않는다. 새 교사 입장 정보는 공개하지 않는 `.local/teacher-access.txt`에 남긴다.

Cloudflare 서버는 자체 주소의 public/를 제공하므로 같은 주소에서 로그인한다. GitHub 화면에도 실제 로그인을 연결하려면 public/config.js의 apiBase를 배포한 부기2 서버의 `/api` 주소로 지정한다. 서버의 ALLOWED_ORIGINS에는 `https://legoschool.github.io`만 추가한다. CORS는 로그인 검증을 대신하지 않는다.

## 확인한 것과 남은 것

로컬 서버 함수 검사에서 학생의 교사 결과 조회, 다른 교사의 학생 조회, 잘못된 응답, 중복 제출, 검토 없는 배정, 로그인 만료, 학생 삭제를 확인했다. 실제 브라우저에서 가상 실계정 생성부터 응답 제출·교사 배정·학생 기록 저장·새로고침 후 기록 유지까지 확인했다. 1440px·390px 화면에서 가로 넘침과 JavaScript 오류가 없었다.

학교망, 학급 동시 접속, 교육 검토, 운영 백업·복원 훈련은 별도 검증이 남았다. 서버가 열리지 않으면 학생 응답을 체험 화면에 입력하지 않고, 교사가 장면을 읽어 주고 종이에 처음 생각과 근거 문장을 적게 한다.
